# d3d12_x.dll

The console's Direct3D 12 runtime. Observed with 1738CA2A (GDK build). The console `d3d12_x.dll` only loads a user-mode driver, which implements the objects; g6shim implements them over the PC's Direct3D 12.

## Exports

| Export | Signature and use |
|---|---|
| `D3D12XboxSetProcessDebugFlags` | `HRESULT (UINT flags)`; the console keeps `flags & 0x81F00001` and returns `S_OK` |
| `D3D12XboxCreateDevice` | `HRESULT (IGraphicsUnknown* adapter, const void* params, REFIID riid, void** device)`. `params` is 0x28 bytes and required (`E_INVALIDARG`); its first two `UINT32`s are a version (`0x1000A` observed) and the process debug flags. Titles pass a null adapter and the PC IID of `ID3D12Device`. |
| `D3D12SerializeRootSignature` | PC signature; the blobs it returns are console blobs |

## Objects

Console objects are not COM objects. Each starts with a 16-byte head:

| Offset | Field |
|---|---|
| +0x00 | function table; every function takes the object as its first argument |
| +0x08 | `UINT32` device-index bits |
| +0x0C | `UINT32` reference count |

Titles use the PC IIDs.

| Object | Console bytes | Table |
|---|---|---|
| device | 0x58 (`+0x18` out-of-line flags) | slots 0 to 43 in PC `ID3D12Device` order, then console-only slots |
| command queue | 0x18 (`+0x10` list type) | slots 0 to 17 in PC order |
| graphics command list | 0x360 (`+0x10` list type) | slots 0 to 8 in PC order, the rest in console order. The bytes after the type are state the title's inline functions use; zeroed, they send every call through the table. |
| descriptor heap | 0x10 | slots 0 to 10 in PC order |
| blob | 0x20 (`+0x10` buffer, `+0x18` size) | slots 0 to 4 in PC order |
| DXGI device | 0x20 | `IUnknown`, `IDXGIObject`, then `GetAdapter` at slot 7 |
| DXGI adapter | 0x18 | slots 0 to 9 in PC order |

Slot 7 of every device child is `GetDevice` and must hand back the console device.

Functions in a console table are plain functions, so results that the PC methods return through a hidden pointer come back by value:

| Function | Console form |
|---|---|
| device `GetResourceAllocationInfo` (slot 25) | `D3D12_RESOURCE_ALLOCATION_INFO* (result, device, visible mask, count, descriptions)` |
| device `GetCustomHeapProperties` (slot 26) | `D3D12_HEAP_PROPERTIES* (result, device, node mask, heap type)` |
| device `GetAdapterLuid` (slot 31) | `LUID (device)` in `rax` |
| descriptor heap `GetCPUDescriptorHandleForHeapStart` (slot 9) | `SIZE_T (heap)` in `rax` |
| descriptor heap `GetGPUDescriptorHandleForHeapStart` (slot 10) | `UINT64 (heap)` in `rax`; titles also call it on heaps that are not shader-visible, where g6shim returns 0 |

## Resources written by the CPU

Console memory is one address space for the CPU and the GPU. A title takes a texture's GPU virtual address (`ID3D12Resource` slot 11) and writes texels through it, laid out as its XG layout says. 1738CA2A reads texture files straight into that memory. On the PC a texture has no GPU virtual address and its memory is not visible to the CPU.

g6shim gives each texture CPU memory of its own, in the linear layout `xg_x` reports, and answers slot 11 with its address. Pages the title writes are copied into the texture before the next command lists run on any queue.

## Command list tables

The graphics command list table keeps the PC order of `ID3D12GraphicsCommandList` except for one block: `BeginQuery`, `EndQuery`, `ResolveQueryData` and `SetPredication` follow `ExecuteBundle`, so the methods from `SetDescriptorHeaps` to `DiscardResource` sit four slots later than on the PC.

| Console slots | PC slots | Methods |
|---|---|---|
| 0 to 27 | same | `QueryInterface` to `ExecuteBundle` |
| 28 to 31 | 52 to 55 | `BeginQuery`, `EndQuery`, `ResolveQueryData`, `SetPredication` |
| 32 to 55 | 28 to 51 | `SetDescriptorHeaps` to `DiscardResource` |
| 56 to 59 | same | `SetMarker`, `BeginEvent`, `EndEvent`, `ExecuteIndirect` (inferred, not yet called) |
| 60 to 66, 68 to 82, 84 and up | | console order, not mapped |
| 67 | | `FlushPipelineX(flags, address, bytes)`: 1738CA2A flushes the range a texture copy wrote with flags 0x20000. The PC orders copies with barriers. |
| 83 | | `CopyTextureRegionX`: `CopyTextureRegion` with a `UINT` flags argument after the box; 1738CA2A passes 0 when uploading textures mip by mip |

Observed calls: `Close` (9), `ClearDepthStencilView` (51) with `(view, 3, ...)`, `ClearRenderTargetView` (52) with `(view, colour, 0, null)`.

| Console slot | DMA command list |
|---|---|
| 0 to 6 | PC order |
| 7 | `GetDevice` |
| 8 | `GetType`, returns 16 |
| 9, 10 | `Close`, `Reset` |
| 11 to 14 | `CopyBufferRegion`, `CopyTextureRegion`, `CopyResource`, `CopyTiles` |
| 15 | `ResourceBarrier` |
| 16 to 18 | `BeginQuery`, `EndQuery`, `ResolveQueryData` (inferred) |
| 19 to 21 | `SetMarker`, `BeginEvent`, `EndEvent` (inferred) |
| 22 and up | console-only, not mapped |

Observed DMA calls: `Close` (9), `CopyBufferRegion` (11) with `(destination, 0, source, 0, bytes)`, `ResourceBarrier` (15) with `(1, barriers)`.

In both tables `ResourceBarrier` is taken to return a `UINT`; g6shim returns 0. Textures may take the vertex and constant buffer and index buffer states: 1738CA2A moves textures to `0x8C3`. On the PC these states are for buffers only, and a texture transition that names them fails the list's `Close`. The DMA engine accepts transitions to any state: 1738CA2A moves buffers to `0xC3` (vertex, index and shader-resource reads) on a DMA list. A PC copy list accepts only the common and copy states. `SetDescriptorHeaps` and `ExecuteBundle` receive console heaps and lists.

## Device slots with console arguments

| Slot | Function | Arguments observed |
|---|---|---|
| 9 | `CreateCommandAllocator` | PC order; takes console list types |
| 12 | `CreateCommandList` | PC order; takes console list types |
| 15, 23, 24 | `GetDescriptorHandleIncrementSize`, `CopyDescriptors`, `CopyDescriptorsSimple` | PC order; take console heap types |
| 48 | `CreateCommandQueueX` | `(desc, riid, queue)`; `desc` is `{UINT32 type, flags, engine or pipe, queue index}`. Types 0 (direct), 2 (compute) and 16 (DMA) observed. |
| 68 | unknown | `(struct*)`, result ignored by the title |
| 69 | unknown | `(UINT32 id, UINT32 value)`, several ids, value 1 or 0xF |
| 73 | `CreateCommandListX` | `(desc, allocator, pipeline state, riid, list)`; `desc` is `{UINT32 type, flags, node mask, barrier batch size}` |
| 78 | `SetFrameIntervalX` | `(output, interval in microseconds, periods, flags)`: `(null, 16667, 2, 0)` |
| 79 | `ScheduleFrameEventX` | `(type, offset, objects, flags)`; `objects` is `{UINT32 count, HANDLE* events}` |
| 80 | `WaitFrameEventX` | `(type, timeout in milliseconds, objects, flags, UINT64* token)`: `(0, INFINITE, null, 0, token)`. 1738CA2A asks only while its token is 0 and keeps it for presenting. g6shim's token is the event's index + 1, with the type in the top byte for types other than 0. |

The byte at device `+0x18` holds out-of-line flags. While it is 0, the title's inline functions write console descriptors and commands straight into memory: 1738CA2A then never calls `CreateConstantBufferView` and fills its descriptor heaps with console descriptors. With 0xFF they call the function tables.

`CheckFeatureSupport` with `D3D12_FEATURE_D3D12_OPTIONS` passes 0x40 bytes; the PC structure is 0x3C bytes.

Constant buffer views (device slot 17) need 16-byte alignment on the console and 256 bytes on the PC, for the address and the size. 1738CA2A creates views of 96, 176 and 368 bytes at 16-byte steps in its upload buffers once, and rewrites the data every frame.

1738CA2A creates textures in the copy destination state and writes them on DMA lists. A PC copy queue requires textures to be in the common state, from which a copy promotes them implicitly on any queue.

The console accepts `D3D12_RESOURCE_FLAG_DENY_SHADER_RESOURCE` on buffers. 1738CA2A creates 36- and 44-byte default-heap buffers with it and moves them to read states. The PC allows the flag only together with `D3D12_RESOURCE_FLAG_ALLOW_DEPTH_STENCIL`.

## Console types

| Kind | Value | Meaning |
|---|---|---|
| command list and queue type | 16 | DMA engine; a DMA list has its own interface and table, slots 0 to 6 in PC order and `GetDevice` at 7 |
| descriptor heap type | 4 | unbounded sampler heap: samplers beyond the usual shader-visible limit, with only transparent black, opaque black and opaque white border colours. 1738CA2A asks for 16384. |

`ExecuteCommandLists` (queue slot 10) receives console command lists.

`PresentX` is queue slot 30: `HRESULT (queue, plane count, planes, parameters)`. A plane starts `{UINT64 pipeline token, UINT32 resource count, UINT32, ID3D12Resource* const* resources}`. 1738CA2A presents one plane holding one 1920×1080 `R8G8B8A8_UNORM` render target, with the token `WaitFrameEventX` gave it. The parameters start `{0, 1}` and are not decoded.
